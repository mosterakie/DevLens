# 真实日志样本

`internal/usecases/samples.go` 里的样本全部取自公开的 GitHub issue，
是开发者在报告问题时粘贴的**生产环境原始输出**，不是编造的示例。

## 为什么用真实日志

构造的示例日志往往"太干净"：格式统一、没有多余噪声、错误关键字齐全。
真实日志不是这样：

- 缩进混乱，制表符与空格混用
- 多行堆栈里夹杂着中间件加的前缀（如 `node_exporter[1070004]:`）
- 同一条日志里混着 INFO 和 FATAL
- 时间戳格式各异，有的带时区有的不带

这些差异恰好是归一化规则最容易漏掉的地方。

## 覆盖范围

| 技术栈 | 条数 |
|---|---|
| Go panic / goroutine 栈 | 6 |
| Java 异常栈 | 3 |
| Python Traceback | 1 |
| Node.js 事件栈 | 1 |
| DNS 解析失败 | 1 |
| 数据库连接故障 | 1 |
| 网络超时 | 2 |

## 能验证什么

`internal/usecases/samples_test.go` 用这批数据检查：

- **指纹互不相同**：15 条样本归一化后不能撞车。若撞了，说明规则过松，
  会把无关故障归为同类。
- **真实日志上幂等**：单元测试用的是构造字符串，这里换成含多行缩进和
  各种噪声的真实日志。
- **时间戳不影响指纹**：在真实格式上验证，而不是只在构造的样例上。

## 局限

这批样本只用于**离线验证归一化规则**。它们没有跑过模型分析——
那一步需要调用外部 API，不能放进单元测试。

样本来源链接保留在 `Sample.Source` 字段里，可以点开核对原文。
